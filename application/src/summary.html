Summertime

Commit together. Settle together.
Executive summary · November 2026
AppsFactory Accelerator, Cohort 2
github.com/linoxbt/summertime

Summertime lets competing importers reserve space in a shared shipping container without seeing each other's volumes or identities. Each importer locks USDCx against a forwarder-signed reservation. If the container fills before the deadline, every payment settles to the forwarder in one atomic Canton transaction. If it doesn't, every importer's funds are released and each claims a share of a failure bond the forwarder posted upfront.

Problem

Small importers can't fill a container alone, so they share one (groupage). On the China–Lagos route, each pays the consolidator upfront and hopes the container fills. Four failures follow:

  • Pay-first risk: money moves before the container is confirmed full.
  • First-mover reluctance: nobody wants to commit first, so containers fill slowly.
  • Competitive leakage: importers learn each other's volumes through the shared shipment.
  • Partial execution: some pay, some don't; shipments slip and refunds are disputed.

Solution

  • The forwarder opens a campaign: capacity, rate per CBM, deadline, and a 1–5% failure bond.
  • Importers reserve privately and lock USDCx in their own token-standard allocation.
  • Full container: one atomic transaction pays the forwarder. Not full: funds released, bond shared.

"Competing importers cannot see each other's reservations, volumes or identities. Your forwarder sees your reservation, exactly as it does today, and so does Summertime, which enforces the settlement rules. Funds move only if the container fills."

Why Canton

Sub-transaction privacy (each importer sees only its own leg), atomic multi-party settlement, and CIP-56 token allocations with USDCx. A public chain would expose every competitor's volume.

Progress (verifiable in the public repository)

  • 51-page build specification (v1.1) with privacy model, threat model and test plan, after a design review that fixed four critical flaws before coding.
  • summertime-core: 16 Daml templates on SDK 3.7.1 against the Canton token-standard V1 interfaces.
  • 20 automated tests passing: atomic six-leg settlement; exact failure bonuses; the forwarder cannot settle alone, overbook, or avoid the bond; importers cannot see each other.
  • Not yet: DevNet deployment, app UI, users or revenue.

Market and customer

Buyer: independent forwarders running groupage containers, China–Lagos. User: SME importers shipping 1–15 CBM. Ideal first customer: a forwarder running two or more groupage containers a month with importers it knows by name. Market size will be built from interview data rather than estimated without a source.
